Before You Start: What’s One Row?

The most important decision in this component is what one row of your table stands for. Go back to the unit of analysis you named in Component 1, Section 3. That’s your row.

If your unit is… One row is… Example columns
Words in a text one word, in order word
Sentences or lines one sentence or line sentence
Entries (dictionary, word list, Swadesh list) one entry form, meaning, language
Texts (speeches, recipes, songs) one whole text title, author, year, text

Your columns should hold what’s in your data, cleaned up. Any new columns you calculate from it (word length, frequency, part of speech…) belong in Component 3.

If you’re comparing several texts, you can either make one table with a column saying which text each row comes from, or make one table per text. Either is fine.

3. Clean Your Data into a List

Your goal here is a Python list of your units: words, lines, entries, or whatever your row is. What “clean” means depends on your data, but most of you will do some version of the following:

  • Trim the edges. Remove anything that isn’t part of your data: Project Gutenberg headers and footers, a table of contents, page numbers, website menus.
  • Split the text into units. For words, use re.split(r"[\W]+", ...), which splits on whitespace and punctuation. For lines, .split("\n") works. For entries, you’ll need to split on whatever marks the start of each entry.
  • Standardize. Use .strip() to remove extra whitespace and .lower() so that The and the will count as the same word.
  • Remove empty strings, which re.split() leaves behind at the start and end of a text. A list comprehension does this in one line: [w for w in words if w != ""].

When you’re done, look at your list. Print the first 20 items, the last 20, and len() of the whole thing. Does anything look wrong? If so, fix it in your code and run everything again. That’s normal, and it’s the whole point of keeping your cleaning in code.

Cleaning means making decisions

Every cleaning step throws something away, so make each one on purpose:

  • re.split(r"[\W]+", ...) splits don't into don and t, and well-known into well and known. Is that OK for your question?
  • .lower() erases the difference between Bill (a name) and bill. In German, it erases the capital letters that mark every noun. Do you need those?
  • Does your data have numbers? Words in a second language? Speaker labels like INTERVIEWER:? Do you keep them or drop them?

There isn’t one right answer. There’s only the answer that fits your questions from Component 1. Whatever you decide, say so in your write-up (Section 2 below).

4. Turn Your List into a pandas DataFrame

This is the same pipeline we used in class (Day 23). First, turn your list into a list of dicts, one dict per row, with your column names as the keys:

rows = []
for w in words:
    rows.append({"word": w})

If each unit has several pieces of information, give each one its own key:

rows.append({"form": form, "meaning": meaning, "language": language})

Then hand the whole list to pandas:

import pandas as pd

df = pd.DataFrame(rows)

Each dict becomes a row, and each key becomes a column. pandas numbers the rows for you (0, 1, 2, …). If your units already have their own numbers, like entries in a dictionary, put the number in its own column (e.g. "entry": 12) so it’s saved with the data.

5. Check Your DataFrame

Before you save, take a look:

  • len(df): about how many rows did you expect? Is this close?
  • df.head() and df.tail(): do the first and last rows look like real data, or like leftover headers and footers?
  • Spot-check a few rows in the middle against your raw file. Did anything get cut off, merged, or split in the wrong place?

6. Save Your DataFrame as a .csv

Save your table into your course_project folder:

df.to_csv("project2_lastname_firstname.csv", index=False, encoding="utf-8-sig")
  • index=False leaves out pandas’ row numbers, which you don’t need in the file.
  • encoding="utf-8-sig" makes sure Excel displays accented and non-Latin characters correctly when you open the file there.

7. Reload Your .csv to Check It

Read the file back in and confirm it matches what you saved:

check = pd.read_csv("project2_lastname_firstname.csv")
print(len(df), len(check))
check.head()

Same number of rows? Same columns? Do the special characters look right? (One thing that will look different: empty cells come back as NaN, pandas’ marker for “nothing here.” That’s normal.) Open it in Excel (or Google Sheets) once, too. This file is what you’ll start from in Component 3, so make sure it’s right now.
